# Projectile rendering preview

`ProjectileRenderer::load` resolves model names from `RocketDefinitions` to original 3O resources and caches each distinct model and animation pairing. An empty model name denotes an instant shot and has no projectile mesh. Invalid names or missing/invalid models are skipped with a diagnostic. Indexed skins use `chasm2.pal`; the helper does not load PNG or glTF replacements.

`ProjectileVisual` is a transient presentation snapshot containing a rocket-definition index, a 3D position in map tiles, yaw/pitch in radians and elapsed time since launch. `render` consumes snapshots with the same player camera, color buffer, and per-pixel depth buffer used for walls and objects. It clips geometry at the near plane, interpolates skin UVs perspectively, and reads/writes depth so projectiles are hidden behind walls and other geometry. Draw it after world geometry and before the weapon/HUD overlay. Invalid pose values and out-of-range or instant rocket types are ignored.

Rocket geometry is rotated around the model's local X axis for pitch and then around Z so its +Y axis faces the given horizontal yaw. Coordinate scale `1/2048`, orientation and the camera conventions follow the existing 3O and [PanzerChasm rocket-drawer](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/client/map_drawer_soft.cpp) research and remain provisional pending comparison against the original. Faces render two-sided, and transparency flags are approximated with palette-index alpha testing. Authored ANI geometry advances using per-projectile launch age. The provisional timing follows the independent PanzerChasm reconstruction: 18 frames per second, rounded to the nearest frame and looping over all frames. Missing, invalid, or vertex-count-mismatched ANI files fall back to the base 3O pose without disabling gameplay. Explosion, impact and trail sprites have separate renderers; The authored `FBright` flag bypasses provisional distance shading for projectile meshes, following the independent reconstruction; original lightmap behavior and interpolation remain incomplete. Solid floors and ceilings contribute to the shared depth buffer.

Projectile trails resolve the authored nonzero `Smoke` field through `[BLOWS]`, including sprite size, looping, gravity and bounce metadata. They emit every half tile along committed 3D motion using reconstruction timing. The client samples before/after each fixed tick, includes terminal impact segments, splits paths at reflector contacts, and clears effects on restart/load. First-tick segments whose origin cannot be reconstructed from events are omitted. Tracking and particle counts are bounded; cross-type translucent ordering, original lighting and exact visual parity remain provisional. Trails never change simulation state.

This is a renderer only. Projectile spawning, trajectory, collisions, damage, lifetime, synchronization and other game rules remain in the simulation. Synthetic tests exercise depth occlusion, instant/invalid types, unsafe resource names, invalid coordinates and near-plane clipping.
