# Explosions and mines

`explosives` is a headless fixed-tick building block, not yet connected to weapon firing or the client. The host supplies current eligible target cylinders and applies the returned damage events once. `resolve_explosion` validates the complete batch before returning any events, rejects duplicate target IDs, and preserves target order. It measures 3D distance to a cylinder's surface and rounds linearly falling damage, matching the local reconstruction. The owner is eligible for damage. The resolver does not apply a separate direct hit, perform occlusion, select destructible objects, trigger scripts, or simulate chains; the host owns those decisions. Treat any collision, elevation and cylinder data supplied by the host as approximations until its geometry is verified.

`MineSystem` uses a deterministic 60 Hz tick, stable IDs, a 4096-mine capacity and caller-supplied living player/actor circles. Placement must be on a validated floor within the 64×64 map. Every successful placement emits `Placed`; after 90 ticks a mine emits `Armed`; a strictly overlapping circle (including its owner) emits one `Detonated` event carrying an `Explosion`, then removes the mine. At tick 1801 it expires before checking proximity. Inputs are fully validated before a tick mutates state. The host must display/remove mine instances, select active targets, process each detonation through the explosion resolver, and persist/synchronize this state for networking and restart.

The 1.5-second arm time, 30-second expiration, 0.5-tile trigger radius, 2.3-tile blast radius and 140 damage come from local reconstruction constants explicitly marked for calibration. They are provisional, not measured original-game behavior. The reconstruction uses no wall-occlusion check for explosion damage; this module does not infer one. It does not interpret rocket data or enable grenades.

The session can explicitly opt in with `Session::set_explosions_enabled(true)` before taking its restart snapshot. Weapon slot 5 then launches physical grenades; physical projectiles with authored `Ard > 200` resolve splash instead of separate direct-hit damage. `SessionEvents::explosions` and `explosion_damage` report the event and pre-armor damage. The hit wall or object still receives its shoot link, while destroyed objects receive destroy links. If a required staged destruction fails, the complete blast and its contact links are rolled back. Mines remain disconnected.

Projectile horizontal collision remains two-dimensional. Splash uses the projectile's launch eye height for player shots and a provisional one-tile height for enemy shots; actor and destructible-object target cylinders also have provisional one-tile height. Blastable objects follow the reconstruction's positive radius, break limit and blow-up requirements. Grenades with gravity, bounce or always-homing flags are rejected until those motions are modeled. Other player weapons and enemy projectiles retain their existing straight-line approximations for these flags. No explosion wall occlusion is inferred.

Mine placement is separately opt-in with `Session::set_mines_enabled(true)`. Slot 6 uses authored ammunition and reload time; failed placement refunds ammunition and cooldown. `Session::mines()` exposes the current authoritative mine snapshot for a renderer or network snapshot, and `SessionEvents::mine_events` carries placed, armed, detonated and expired changes. The client must consume both. A new mine begins at age zero and advances on the next tick. Mines use the provisional flat floor currently supplied by the session. Mine detonation has no projectile contact, so it does not emit shoot links; destroyed objects still receive destroy links. If a required scripted destruction cannot be committed, the entire mine tick is rolled back and the armed mine can retry.

If staged contact or destruction preflight rejects a projectile blast, the projectile is restored to its pre-tick state and its impact event is suppressed; it can retry when the blocking state changes. This does not refund the fired ammunition. Blast damage events describe only targets actually updated after contact scripts have run. Projectile trajectories are still traced as a batch before impacts are resolved, so multiple same-tick impacts can use stale collision targets. Mine ticks clone active mine state, and detonation batches clone session state for rollback; large numbers of simultaneous mines can be expensive.
