# Save envelope and content identity

`save_format` supplies bounded, in-memory primitives. It does not read or write files, reconstruct content, or implement a user-facing save feature. No game asset bytes are stored by the envelope or manifest.

Version 1.0 is eight-byte magic `OPCHSAVE`, little-endian u16 major and minor, 32-byte content identity, little-endian u32 payload length, opaque payload, and SHA-256 of all preceding envelope bytes. The payload is limited to 16 MiB; decoding rejects unsupported versions, truncation, trailing data, oversized payloads, checksum mismatch, and, when requested, content mismatch. SHA-256 is an integrity check, not authentication. Any future payload decoder must validate its own schema and bounds before changing live state.

A content manifest hashes an ordered, length-delimited canonical manifest: each normalized lowercase relative resource name is paired with an explicit missing marker or a byte length and SHA-256. Sorting makes insertion order irrelevant, and missing differs from present-but-empty. The host must include all actual gameplay dependencies and decisions, including resolved asset fallbacks, rules version, difficulty, and capability configuration; merely using the source label or map filename is insufficient. The streaming digest API trusts the caller's provided byte count and digest. File access and atomic replacement remain future work.

`session_codec` adds a versioned UTF-8 JSON payload inside this envelope, capped at 4 MiB. Its current schema is version 2; version 1 is explicitly migrated with inactive source lights and a fresh light-tick epoch, while unknown versions and unknown fields are rejected. Integer fields retain the explicit u8/u16/u32/u64 and i32 ranges of snapshot DTOs; the two map-cell `usize` fields are restricted to 0..63 for cross-platform portability. Finite f32 values round-trip through the codec; non-finite values are rejected. Encoding is bounded while writing; decoding limits input before parsing and checks vector cardinalities afterward. JSON has no attacker-declared array lengths, though parsing can allocate more memory than the input size. Decoded snapshots are untrusted and must be restored through `Session::restore_from_baseline` against verified content; decoding alone does not validate gameplay semantics or authenticate the data. Future schemas require an explicit versioned decoder or migration and must not reinterpret version 1 in place.
