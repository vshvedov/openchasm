# Desktop builds

The default client uses bundled static SDL2, CMake, and rodio playback. The CI matrix builds and tests the client on Linux, Windows, and macOS, and tests the headless library with `--no-default-features`. Linux client builds need the ALSA development headers; the checked-in workflow lists its window-system development packages. Actual desktop audio, input capture, and game-data behavior still require testing on each platform.

The SDL CMake toolchain is configured to avoid a Linux PipeWire build issue and to preserve the static SDL compile flags. A custom CMake toolchain disables the Rust `cmake` crate's automatic target-system inference, so the checked-in toolchain sets the CMake target system for Linux/Windows/macOS cross-OS builds. It does not install or select a cross compiler, linker, target SDK, or system libraries. Supply these using Cargo/`cc` target-specific environment variables and CMake as appropriate; for macOS this includes a compatible Apple SDK. A missing or incompatible compiler should fail configuration rather than silently building host-native SDL objects. Same-OS cross-architecture builds also need an appropriately configured compiler and SDK.

After changing toolchains or switching targets, clear the affected target's cached SDL build artifacts or use a fresh `CARGO_TARGET_DIR`; CMake caches compiler and platform choices. `cargo check` alone does not link the executable and cannot establish that a native dependency has the correct object format. Run `cargo build --locked --target <target>` and test the executable on the target system. A local Linux host with no MinGW compiler was used to verify that a fresh Windows GNU client cross-check fails at the compiler test, while headless library checks succeeded for Windows GNU and Apple ARM targets. No successful cross-linked client is claimed.
