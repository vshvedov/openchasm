# Player and pickup snapshots

The headless inventory, protective powerup, vertical motion, world, and pickup modules expose explicit value snapshots and validated restore methods. These are building blocks only; they are not a Session save format or a file codec. Restore validates a complete subsystem snapshot before changing that subsystem. A future Session loader must construct a fresh level and restore all subsystems on a temporary Session before publishing it.

Inventory restoration validates health, armor and ammo against the loaded weapon definitions. Vertical snapshots contain feet, velocity and grounded state; the target's loaded physics configuration and caller-supplied current floor/ceiling are checked, while temporary head overlap with a lowered ceiling is accepted because Session can hold its previous vertical state until clearance returns. World snapshots contain player pose and stable ordered wall records; wall index, authored cell and texture must match the reconstructed world before restoring moved endpoints and collision flags. Pickup snapshots contain original map cells, moved positions, script enabled flags and collected flags; loaded definitions, radii and difficulty are not copied from the save. Cell sets must match exactly and contain no duplicates.

The future full loader must cross-check wall transforms with process state and vertical/pickup positions with other subsystems, and verify content identity and capability flags. Restoring these modules independently does not establish those cross-subsystem invariants. Floating-point values remain ordinary finite `f32` state; a future portable codec must define their binary representation and reject malformed values.
