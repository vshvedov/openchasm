# Object shots and destruction

Level objects can have `shoot` and `destroy` process links. The bundled game manual describes `BLim` as initial object health and says zero-health objects are indestructible; `BlowUp` controls destruction behavior. The installed campaign scripts contain 42 shoot links (21 attached to walls and 21 to level objects) and 25 destroy links attached to level objects. For example, level 01's `lock01.3o` at (22,55) has BLim 10 and a destroy link to process 1.

`ObjectCombat` indexes level objects that either have positive BLim or are explicitly referenced by a shoot/destroy link. It exposes a pure nearest-ray query and a separate damage application, so a caller can compare object distance against wall and actor distances before applying any effect. A positive hit emits an `ObjectHitEvent`; dispatch `shoot` for each hit, and `destroy` exactly once when the event reports `destroyed`. Wall shoot events are the caller's responsibility. Normal difficulty filters placement flags; script enable and position updates are supported, while destroyed objects cannot be resurrected through `set_enabled`.

This first pass uses two-dimensional approximate circular hit volumes from GoRad with a 0.125-tile minimum. It is not accurate mesh intersection, does not include vertical position, does not block shots with unlinked indestructible scenery, and does not model object replacements, sound, break effects, splash damage, friendly damage, or multiplayer replication. GoRad is a movement-collision field, so its use for shot hit testing is an explicit approximation. `BlowUp` is retained in hit events for future destruction handling, but no replacement model or effect is inferred yet. Item-category pickups are not indexed.

A full-corpus smoke check confirms the subsystem tracks all 46 object-bound shoot/destroy link targets across levels 01–19 on normal difficulty. Unit tests cover object-versus-object ordering, repeated shots on indestructible targets, one-shot destruction, projectile radius, difficulty, moved objects, invalid input, and exclusion of unrelated decorations.

The game session now compares instant-shot object hits against walls and actors, applies object damage, sends `shoot` links on impact and `destroy` links on the first destruction, and unlocks a process referenced by a destroy link. The viewer hides destroyed objects. Physical projectiles also collide with tracked objects; player impacts dispatch shoot and destroy links. Object collisions with movement remain unsupported.

Scripted object replacements can synchronize through `apply_transition` or the atomic ordered `apply_transitions` batch. The caller should stage or clone authoritative object states and combat together, then publish both only if validation succeeds; this module does not commit simulation or renderer changes. Each transition validates its existing raw type, destination definition and reset health, and updates the new hit radius, health and blow-up value. Level-object placements are retained even when initially decorative so a later replacement can become shootable. Position, difficulty eligibility, enable state and coordinate-based shoot/destroy links survive replacement; destroyed state is cleared. The `dummy.3o` definition is treated as an empty, non-shootable cell even if it retains a link. These hit shapes and dummy semantics remain provisional.

The reference shot query skips models whose authored GoRad is zero or negative, including linked destructible placeholders; projectile radius does not make them ray targets. Replacements re-evaluate their authored radius. In level 08, the initial `(6,28)` target is such a placeholder; destroying the neighboring `(6,27)` model triggers its replacement with a positive-radius model. This sequence is derived from the installed script and reference engine, not a claim of full encounter completion.
