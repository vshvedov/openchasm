# Experimental level processes

The fixed-tick runtime handles floor-cell triggers, nearby `link` triggers via the use key, wall `move` and `rotate` actions, `lock` and `unlock` actions, `StartDelay`, `Speed`, `BackWait`, and circular `waitout` zones. `waitout` reverses a returning process when the player is within its radius. Wall targets use their original map grid cells, and processes can move multiple segments together.

Each observed `rotate` action has five arguments: target cell x/y, pivot x/y in map units, and a signed angle. The [original editor documentation](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/docs/CSM_EDIT.TXT) identifies the pivot as a global coordinate and the last argument as an angle, but does not specify its units or handedness. The implementation provisionally interprets it as signed degrees and rotates the wall around that pivot. Rotational travel time uses the largest endpoint's arc length and the same provisional speed conversion as a translation. The unit, sign, timing and original behavior require visual comparison against the game.

Moving solid walls are sampled along their path and stop before overlapping the player's preview collision circle, resuming when the obstruction moves away. Sampling and the 0.18-tile radius are provisional. Moving walls do not yet push or crush players, do not check monsters or objects, and do not implement the exact `CheckGo`/`CheckBack` semantics. Other action types, speed overrides, unresolved wall targets, or multiple actions targeting the same wall disable a process entirely to avoid executing only part of its behavior. Initially locked processes can be unlocked by supported switch actions; key-gated processes consult the owning player's supplied key state. The game loop must synchronize that state after pickup. Lock changes currently occur on activation even when a start delay is set. Process attempts emit accepted, locked, unsupported, busy or missing outcomes. The session forwards accepted and locked outcomes to mission messaging; audio remains unimplemented. Multiple processes affecting the same wall are not yet coordinated. `check` reports how many initially unlocked moving processes are currently supported; this is not a count of all runnable level logic.

The original level 06 file includes an action section after a commented-out process header; the parser reports it rather than silently assigning it to a different process.

A standalone smoke test parsed and exercised each trigger from all 20 installed map/process pairs and confirmed finite wall coordinates. Synthetic tests cover both rotation directions, returning to the initial wall position, swept obstruction for rotating and translating walls, disabled mixed/invalid actions, key gating and triggers. The real-level smoke test is not an original-game fidelity test.

Exit processes with a positive EndDelay can activate without movement. A syntactically valid playani action in such an exit is accepted as a presentation placeholder, but animation is not played. Unsupported state-changing actions still prevent the whole process from activating.
