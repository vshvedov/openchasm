# Process and object snapshot components

`ProcessRuntime::snapshot(&world)` returns typed process state and rejects capture while process effects are undrained. It includes process phase and remaining delay, progress for each authored wall and object motion, lock and hazard/wind state, previous cell types for reversible changes, wall elevations, ordered wall identities, object poses, raw cell types, player keys, and floor-trigger debounce state. `restore(&snapshot, &world)` checks identities and values and applies the entire component atomically. Restore requires a freshly constructed runtime for the same script and loaded level; removed process objects cannot be reintroduced into a runtime that has already discarded them. `World` geometry is saved separately.

`ObjectStates::snapshot` stores each map cell's current type, health, position and angle. `ObjectCombat::snapshot` stores cell type, hit health, position, enabled and destroyed state. Their restore methods validate all entries before changing anything; combat derives target radii and other static properties from the loaded object definitions. They do not validate the content package or script itself.

These are component data structures, not a save-file format or a complete session snapshot. An eventual save loader must verify a content fingerprint, restore all components into a temporary session, validate cross-component type/health/pose and wall consistency, restore active hazard and wind fields, reconcile presentation and other subsystem state, and publish only after all checks pass. Failed loads must leave the live session untouched. Runtime motion timing and collision remain subject to existing approximations.
