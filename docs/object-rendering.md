# Static 3O preview rendering

The viewer resolves map item and level-object placements through the existing object definitions. It loads each referenced original 3O file once, applies the shared palette, and renders the placed instances with the eighth-turn angle and original model-coordinate scale recorded in [model-format.md](model-format.md). Instances retain their source grid cell so gameplay can hide a collected pickup without altering other instances using the same mesh.

The software rasterizer clips polygons against the near plane and interpolates texture coordinates perspectively. A depth buffer shared with wall pixels hides objects behind walls while permitting objects to appear through masked wall holes. It also resolves overlap between object polygons. A polygon carrying transparency-related flag bits skips skin palette index 255. glTF-only models are supported; missing or invalid models are skipped with a diagnostic.

This remains a preview. Object animation supports a subset of script triggers described below; object poses can be driven by supported map processes. Skin replacements, sprite effects, shadows and dynamic lighting are not implemented. Faces are currently rendered two-sided; translucent polygons are composited with a bounded per-pixel layer buffer and provisional opacity. Objects start at height zero, and the flat floor/ceiling renderer does not yet contribute depth, so sloped or stacked geometry and polygons extending through floors can display incorrectly. Original camera height, material rules, skin offset handling, and object orientation still need direct comparison with the game.

CAR actor meshes are cached by resource path, retain body animation slots, use the CAR-specific texture coordinates, and maintain independent presentation clocks by placement index. The viewer supplies an animation mode and fixed-tick delta; clocks reset when the mode changes. This is presentation only, and gameplay AI remains in the shared simulation.

Animation-slot mappings are provisional: idle prefers slot 2, run slot 0, melee attack slots 6, 7 or 8, and death slots 16 or 17. Idle/run fallback and remote-attack slot 5 are used when a preferred slot is missing; a model without any applicable animation uses its base mesh. Idle, run and attack loop, while death holds the last frame. The 18 frames per second rate is informed by [PanzerChasm's constants](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/game_constants.hpp), but behavior and timing still require comparison against the installed game. If gameplay hides an actor immediately on death, its death animation cannot appear until visibility is changed. Detached parts, attack muzzle effects and actor-specific exceptions are not yet animated. Extensionless glTF actor definitions such as Faust are supported; unresolved models are skipped with a diagnostic.

`playani` effects can start original object ANI geometry: the script number is interpreted as the `#newobjects` index plus 33, and every matching level-object placement with a compatible animation is restarted. This follows the bundled manual's description and [PanzerChasm's model-number mapping](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/server/map.cpp); script IDs below 33, including the special value 1 seen in several maps, remain unexplained and are ignored. Item definitions and CAR actors are not targeted. The renderer reports how many placements were started, and its caller must advance presentation state once per simulation tick and reset it on level restart.

Object clips currently begin stopped on ANI frame 0, loop all frames at the provisional 18 FPS rate after a `playani` trigger, and can be restarted repeatedly. The timing, loop endpoints, `%` animation marker and initial playback state need comparison with the original: PanzerChasm normally starts many objects automatically and additionally supports `stopani`, which this renderer does not yet implement. Missing, malformed, or vertex-count-mismatched ANI files fall back to the base model with a diagnostic. Mesh cache keys include both model and animation paths, so different definitions can share geometry names without sharing incompatible animations. The real Power Station resource's `playani 58` targets ten `vibro.3o` placements in the installed full archive.
