# In-memory Session snapshot

`Session::snapshot(content_digest)` captures explicit component DTOs at a completed simulation tick and rejects undelivered process effects or wind errors. `Session::restore_from_baseline` builds and validates a candidate from a caller-supplied fresh same-content Session, returning it without modifying the baseline. The host must compute and verify the digest from all resolved gameplay dependencies and rebuild presentation before publishing the candidate. This API is not a file format or user-facing save feature.

The candidate restores inventory, powerups, pickups, player and vertical state, actor and AI state, combat cooldown, process state, projectiles and sparse per-projectile heights, mines, object state and combat state, mission, hazards, wind, quake, ambient, and teleport rearm. Capability and content mismatches reject the restore. It validates keys, actor/clip and owner IDs, projectile-height references, active hazard/wind IDs and authored zone definitions, object types and poses, removed process object justification, pickup synchronization, and wall collision flags.

The current version deliberately rejects states with moved wall or object process progress, differing wall/object poses, nonzero wall elevations, nonzero wind grids, or ambient/quake grids different from the fresh baseline. Their histories cannot yet be proven from current snapshots. It also rejects an ObjectCombat configuration without matching ScriptedObjects definitions. Therefore many ordinary mid-level states are not restorable yet. In particular, this is not a complete Session save or multiplayer snapshot.

This validation does not establish the authenticity of a save, prove every possible state was reached by legal gameplay, verify animation scene state, or make floating-point evolution bit-identical across architectures. SHA-256 content identity and envelope checksums are not authentication. A future portable codec must apply bounded decoding, and a disk layer must use platform-aware atomic replacement.
