# Mission completion and messages

The bundled modding manual describes `EndDelay` as the delay in seconds from a procedure's activation to ending the map. It explicitly says the value `13` means a one-second delay in the remaster. `0` means no level end in the independent [PanzerChasm process implementation](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/server/map.cpp). Every installed campaign level 01–19 contains one process with `EndDelay`; the briefing map 99 has none. Several exit processes contain actions such as `playani`, and other exits use locked, linked or floor-triggered processes, so level completion must be tied to successful procedure activation rather than raw key presses or coordinates alone.

`#mess N` blocks contain `Delay` and `TextA` through other lettered lines, each with x/y coordinates and quoted text. The `OnMessage`, `FirstMessage`, and `LockMessage` properties of a process reference these blocks. The mission parser retains text, slot, and coordinates; the window layer chooses how to display them. The local archive has 69 message blocks across levels 01–19 and 99, and the parser reports no diagnostics on the installed files.

`MissionState::attempt(process_id, accepted)` receives **real** process activation decisions from the process runtime, not prospective input alone. Accepted events schedule a completion timer and emit OnMessage; an attempted activation can emit FirstMessage once, and a denied attempt can emit LockMessage. `advance(dt)` counts down with simulation time and emits `LevelComplete` once. When multiple exits are scheduled, the earliest deadline wins. The caller handles map changes and message presentation; this state machine does not unlock processes, execute actions, or choose a next campaign map.

The precise interaction between end timers, process reversal and movement, message filtering, simultaneous clients, demo restrictions, campaign transitions, and deathmatch is not yet validated. The one-shot and earliest-deadline policies are explicit provisional choices. There is currently no reference-style message throttling or completed campaign/menu flow.
