# Player vertical motion

`VerticalState` is a rendering- and network-independent player feet elevation, velocity and grounded state. The authoritative session supplies floor and optional ceiling heights in map-tile units and advances the state with a finite timestep. `VerticalBounds::flat_room()` is a provisional floor at 0 and ceiling at 2; passing `None` for the ceiling permits open space. The current map reader exposes floor and ceiling texture IDs rather than individual geometric heights, so the host must determine plane bounds; an empty or sky texture is not automatically interpreted as absent geometry.

`step(dt, jump_pressed, bounds)` treats `jump_pressed` as a press edge. A grounded press applies a vertical impulse; an airborne press is ignored. The integrator subdivides up to 1/120-second increments, caps downward speed, lands on the floor, and clamps the head below a supplied ceiling. `VerticalEvents` reports jumping, landing, and ceiling contact. When the player cannot fit between supplied planes, or inputs/configuration are invalid, `step` returns an error without changing state. It accepts positive timesteps up to one second, or a zero timestep as a no-op. A raised floor can carry the feet upward; a lowered floor allows them to fall. More complete platform physics belongs to the session and geometry layer.

The default values are informed by the independent [PanzerChasm constants](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/game_constants.hpp) and [player implementation](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/server/player.cpp): gravity 9.8 tiles/s², maximum vertical speed 5 tiles/s, jump impulse 2.9 tiles/s, body height 0.9 tiles, eye height 0.75 tiles, and a two-tile-high room. The reference marks jump calibration as unfinished; these are not measurements from this Steam installation. The Rust integrator is independently implemented and uses bounded substeps. All values can be supplied explicitly through `VerticalConfig`.

The subsystem does not implement input handling, dynamic object platforms, stepping onto objects, horizontal clearance, changing raised-wall collision, crushing, fall damage, audio, animation, or replication. The caller can use `feet()`, `head()`, and `eye()` for those systems but must align wall, object and plane projections to the same vertical coordinate space. The existing preview's symmetric wall/plane projection assumed a camera halfway up a wall, so changing camera height requires coordinated rendering changes rather than only offsetting a sprite.

Synthetic tests cover a full jump arc and landing, ceiling clearance, airborne input, changing floors, invalid state inputs, open ceilings, and equivalent fixed-step timings. Original jump feel and geometry still need direct gameplay comparison.


The session now advances this state on each fixed tick; Space and the right mouse button send a jump press edge, while the left mouse button fires. Restart restores the initial cloned vertical state. The renderer supplies the same eye elevation to wall, floor/ceiling, actor/object and projectile-model projection. A nearby raised solid wall supplies a provisional overhead clearance limit, and wall movement collision accounts for the player's changing head height while retaining the earlier ground-level threshold. Player hitscan wall blocking uses the current eye height.

The session currently assumes a flat floor and two-tile-high ceiling everywhere, including areas that visually show sky. Floors, object platforms and walls have not been converted into complete vertical collision volumes; a lowering wall can still overlap the player and does not crush or move them. Actor movement, enemy attacks and projectile simulation remain two-dimensional, with projectile visuals drawn at their provisional fixed world height, so jumping does not yet avoid or aim attacks with full three-dimensional accuracy.

The session can stand on known ordinary object tops and pull the player upward when an attempted horizontal move contacts a top within 0.4 tiles and there is body clearance. Pull speed is 2.5 tiles/second, following the independent reconstruction; jump timing and original gameplay remain unverified. Unknown heights and obstructing geometry stay blocking. Player snapshots reconstruct the support floor from their saved position and feet height. Curved model footprints remain cylindrical approximations.
