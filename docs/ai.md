# Provisional enemy AI

`EnemyAi` holds per-placement brains separate from actors, the renderer, and transport. Call `tick` once per 60 Hz simulation tick with actor definitions and the authoritative world. Living, difficulty-enabled actors acquire a player within eight tiles when an opaque wall does not interrupt the sight line, turn toward the last known position, and chase it. The movement speed uses the data table's `SPEED / 10` units per second and stops actors whose speed is two or less, following the independent [PanzerChasm monster implementation](https://github.com/Panzerschrek/Chasm-Reverse/blob/master/src/server/monster.cpp); collision radius derives from `WRad / 256`. Dead actors stop updating and difficulty flags disable actors at load.

When within 0.8 tiles and in sight, actors with a positive kick value emit a melee attack event using the definition's kick damage, at most once every 60 ticks. The caller must apply damage, display animation and audio, and decide death and respawn behavior. The caller can also alert an actor to a position after a hit. Actor IDs in events are stable source placement indices. The AI neither performs network communication nor uses a real-time clock.

This is an initial simulation, not a 1:1 reconstruction. Its detection range, line-of-sight handling, attack reach and timing, turning, target persistence, and collision response need comparison against original gameplay. It has no resolved projectile simulation, pathfinding around obstacles, vertical movement, object or actor collisions, wind, sounds, animation state machine, monster-vs-monster targeting, or player death rules. Movement checks walls in bounded substeps and treats 1–86 as opaque for vision and the world's `blocks_movement` property as collision. Transparent and invisible walls do not obstruct sight. These are provisional, particularly around dynamic wall materials and one-sided geometry.

## Ranged launch events

`tick_with_rockets` additionally resolves each actor's `Rock` value through the parsed `chasm.inf` rocket table. On clear sight at a distance beyond melee range, it emits a ranged event with rocket ID, table power, launch origin, target snapshot, and an `instant` flag derived from whether the rocket has a 3D model. Melee takes priority at close range; a single provisional 60-tick cooldown is shared between melee and ranged actions. Invalid IDs and nonpositive power generate no ranged event. The basic `tick` method remains melee-only.

A physical rocket event is a launch, **not damage**: the owning simulation must move it over time and apply damage only after collision. Instant events likewise require the owning simulation to resolve the hit. As an interim shot-obstruction rule, any intersected wall with ID 1–120 blocks a ranged launch even if it is transparent; wall-specific `gso` shoot-through flags are not yet represented in this subsystem. Reload timing, accuracy, projectile speed, gravity, area damage, behavior behind cover, sound, animation, and initial attack delay remain unverified. Test calls using actual actor and rocket definitions in an unobstructed synthetic scene produced 155 instant and 279 physical launch events across placements in maps 01–19; that check validates data wiring rather than gameplay fidelity.
