# Explosions and mines

`explosives` is a headless fixed-tick building block, not yet connected to weapon firing or the client. The host supplies current eligible target cylinders and applies the returned damage events once. `resolve_explosion` validates the complete batch before returning any events, rejects duplicate target IDs, and preserves target order. It measures 3D distance to a cylinder's surface and rounds linearly falling damage, matching the local reconstruction. The owner is eligible for damage. The resolver does not apply a separate direct hit, perform occlusion, select destructible objects, trigger scripts, or simulate chains; the host owns those decisions. Treat any collision, elevation and cylinder data supplied by the host as approximations until its geometry is verified.

`MineSystem` uses a deterministic 60 Hz tick, stable IDs, a 4096-mine capacity and caller-supplied living player/actor circles. Placement must be on a validated floor within the 64×64 map. Every successful placement emits `Placed`; after 90 ticks a mine emits `Armed`; a strictly overlapping circle (including its owner) emits one `Detonated` event carrying an `Explosion`, then removes the mine. At tick 1801 it expires before checking proximity. Inputs are fully validated before a tick mutates state. The host must display/remove mine instances, select active targets, process each detonation through the explosion resolver, and persist/synchronize this state for networking and restart.

The 1.5-second arm time, 30-second expiration, 0.5-tile trigger radius, 2.3-tile blast radius and 140 damage come from local reconstruction constants explicitly marked for calibration. They are provisional, not measured original-game behavior. The reconstruction uses no wall-occlusion check for explosion damage; this module does not infer one. It does not interpret rocket data or enable grenades.
