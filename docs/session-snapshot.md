# In-memory Session snapshot

`Session::snapshot(content_digest)` captures explicit component DTOs at a completed simulation tick and rejects undelivered process effects or wind errors. `Session::restore_from_baseline` builds and validates a candidate from a caller-supplied fresh same-content Session, returning it without modifying the baseline. The host must compute and verify the digest from all resolved gameplay dependencies and rebuild presentation before publishing the candidate. This API is not a file format or user-facing save feature.

The candidate restores inventory, powerups, pickups, player and vertical state, actor and AI state, combat cooldown, process state, projectiles and sparse per-projectile heights, mines, object state and combat state, mission, hazards, wind, quake, ambient, and teleport rearm. Capability and content mismatches reject the restore. It validates keys, actor/clip and owner IDs, projectile-height references, active hazard/wind/source IDs and authored zone definitions, object types and poses, removed process object justification, pickup synchronization, and wall collision flags.

The runtime validates wall and object poses and vertical offsets against saved per-motion progress and the fresh baseline, within a 0.002-tile (or raw-unit) tolerance for incremental floating-point drift. Translations and elevations can be combined, and an isolated horizontal rotation is supported. A rotation sharing its target with another horizontal motion is rejected when moved, because the order of those operations is not recorded. Shared wall cells with different elevations are also rejected. Committed wind activation/deactivation and immediate ambient/quake and wall material changes are recorded in order as process identities, with at most 4096 entries and 16,777,216 conservatively charged cell writes. Restore replays the corresponding compiled, verified-content commands from the fresh baseline and compares exact grids and active wind membership. Wall replay also validates stable wall cells, material availability and GFX flags, then checks world textures, runtime raw types, movement flags, and geometry against the fresh baseline. Failed transactions and delayed schedules are not recorded; successful delayed actions are recorded at execution. Overflow makes capture or restore fail closed. Direct out-of-band grid changes are not journalled and fail validation. It also rejects an ObjectCombat configuration without matching ScriptedObjects definitions. Therefore many ordinary mid-level states are not restorable yet. In particular, this is not a complete Session save or multiplayer snapshot.

This validation does not establish the authenticity of a save, prove every possible state was reached by legal gameplay, verify animation scene state, or make floating-point evolution bit-identical across architectures. SHA-256 content identity and envelope checksums are not authentication. A future portable codec must apply bounded decoding, and a disk layer must use platform-aware atomic replacement.

The effect journal proves only that grid values follow an ordered sequence of authored effects. It does not prove that process triggers, locks, or timing were reachable in actual gameplay; a forged but plausible journal can still pass. Authenticated server state or a trusted full simulation replay is needed for that stronger guarantee.

Source lights use the same bounded journal with activation/deactivation timestamps on the authoritative live-tick counter. Restore verifies their authored definitions and lifecycle order, reconstructs elapsed ticks without replaying time one tick at a time, and cross-checks active membership against the process snapshot. Source tick overflow fails snapshot capture closed. The journal does not authenticate actual gameplay or prove past trigger timing. Legacy schema-v1 codec payloads migrate as inactive sources at tick zero, consistent with the former active-source capture restriction.
